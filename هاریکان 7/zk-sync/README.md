# آرومین — سرویس تخلیه دستگاه حضور و غیاب (ZKTeco، TCP 4370)

## این سرویس چه کار می‌کند

- با SDK (کتابخانه pyzk) و از طریق **TCP روی پورت 4370** مستقیم به دستگاه وصل می‌شود.
- رکوردهای تردد و نام کاربران را **فقط می‌خواند**. اتصال از یک لایه «فقط‌خواندنی» رد می‌شود و دستورهای `clear_attendance`، `clear_data`، `delete_user` و مشابه آن‌ها اصلاً قابل اجرا نیستند. پس هیچ رکوردی از دستگاه پاک نمی‌شود و سیستم‌های دیگری که به دستگاه وصل‌اند آسیبی نمی‌بینند.
- **جلوگیری از تخلیه تکراری:** هر رکورد با کلید یکتای «دستگاه + کد پرسنلی + زمان + نوع تردد» ذخیره می‌شود. در هر تخلیه همه رکوردهای دستگاه خوانده می‌شوند، ولی فقط رکوردهای تازه ثبت می‌شوند و بقیه با عنوان «تکراری» کنار می‌روند. اگر تعداد رکوردهای دستگاه از آخرین تخلیه تغییری نکرده باشد، تخلیه خودکار اصلاً خواندن کامل را انجام نمی‌دهد.
- **ویرایش امن:** مقدار اصلی دستگاه (`raw_*`) هیچ‌وقت تغییر نمی‌کند و ویرایش روی ستون‌های جداگانه انجام می‌شود. به همین دلیل رکوردی که ویرایش یا حذف شده، در تخلیه بعدی دوباره وارد نمی‌شود. حذف «نرم» است و قابل بازگردانی است، و همه تغییرها در تاریخچه ثبت می‌شوند.
- **زمان‌بند داخلی:** برای هر دستگاه یک بازه جدا تعریف می‌شود (۱ تا ۱۴۴۰ دقیقه، مثلاً ۵ یا ۱۰۹ دقیقه).
- **گزارش‌ها:** کارکرد روزانه شامل اولین ورود، آخرین خروج، جمع کارکرد و اختلاف با ۷:۳۰ موظفی، و خلاصه دوره شامل کسرکار، اضافه‌کار و روزهای ناقص. همه گزارش‌ها خروجی CSV مناسب اکسل دارند.

## نصب روی Debian 11/12

```bash
# پوشه را با WinSCP روی سرور کپی کنید، مثلاً در /root/aromin-zk-sync
cd /root/aromin-zk-sync
sudo bash deploy/install.sh
```

اسکریپت نصب این کارها را انجام می‌دهد:

- پایتون و محیط venv را نصب می‌کند.
- کاربر سیستمی `aromin-zk` را می‌سازد.
- سرویس systemd به نام `aromin-zk` را راه می‌اندازد. این سرویس همیشه در حال اجراست و بعد از ری‌استارت سرور خودکار بالا می‌آید.
- یک **کلید API** می‌سازد و آن را نمایش می‌دهد. این کلید را یادداشت کنید.

تنظیمات در فایل `/etc/aromin-zk/aromin-zk.env` است.

### دستورهای مفید

```bash
systemctl status aromin-zk        # وضعیت سرویس
journalctl -u aromin-zk -f        # لاگ زنده
systemctl restart aromin-zk       # ری‌استارت بعد از تغییر تنظیمات
```

## اتصال به سامانه حضور و غیاب آرومین (پیشنهادی)

این سرویس داخل پروژه `aromin-hozour` است و پنل از طریق سرور اصلی به آن وصل می‌شود؛ تنظیم Nginx و CORS لازم نیست.
فقط در `server/.env` مقدار `ZK_SERVICE_URL=http://127.0.0.1:8470/api` و `ZK_SERVICE_KEY=<کلید API>` را بگذارید.
سرور اصلی تغییرات را از `GET /api/changes?after_rev=N` می‌خواند و به کارکرد تبدیل می‌کند.

## اتصال صفحه داشبورد مستقل (اختیاری)

**روش پیشنهادی (روی همان دامنه داشبورد):**

1. محتوای `deploy/nginx-snippet.conf` را در بلوک `server` مربوط به `dashboard.arominco.com` اضافه کنید.
2. دستور `nginx -t && systemctl reload nginx` را اجرا کنید.
3. در صفحه، بخش «تنظیمات اتصال» را باز کنید. آدرس را `/zk-api` بگذارید و کلید API را وارد کنید.

**روش ساده‌تر:** صفحه داخل خود سرویس هم سرو می‌شود. اگر `AZK_HOST=0.0.0.0` باشد، از آدرس `http://SERVER-IP:8470/` باز می‌شود. در این حالت حتماً پورت را با فایروال محدود کنید.

## ⚠️ نکته مهم شبکه

دستگاه باید از سروری که سرویس روی آن اجرا می‌شود **قابل دسترسی** باشد.

- اگر سرور در ابر آروان است و دستگاه در شبکه داخلی دفتر:
  - یا روی مودم/روتر دفتر پورت 4370 را به IP دستگاه فوروارد کنید و **فقط به IP سرور اجازه دسترسی بدهید**. حتماً روی دستگاه Comm Key هم بگذارید.
  - یا (امن‌تر) سرور و دفتر را با VPN مثل WireGuard به هم وصل کنید.
- روش جایگزین: سرویس را روی یک کامپیوتر یا مینی‌پی‌سی دبیان **داخل دفتر** نصب کنید.

## تست بدون دستگاه

```bash
AZK_DRIVER=fake python3 tests/test_sync.py
```

در `tests/test_sync.py` این موارد تست می‌شوند:

- تخلیه دوم هیچ رکوردی را تکراری ثبت نمی‌کند.
- رکورد ویرایش‌شده یا حذف‌شده در تخلیه بعدی برنمی‌گردد.
- هیچ رکوردی از دستگاه پاک نمی‌شود.
- دستور پاک کردن مسدود است.

## API (خلاصه)

| متد | مسیر | کار |
|---|---|---|
| GET/POST | `/api/devices` | فهرست / افزودن دستگاه |
| PUT/DELETE | `/api/devices/{id}` | ویرایش / حذف از فهرست (رکوردها می‌مانند) |
| POST | `/api/devices/test` | تست اتصال قبل از ذخیره |
| POST | `/api/devices/{id}/sync` | تخلیه دستی |
| GET | `/api/attendance` | ترددها با فیلتر تاریخ، پرسنل، دستگاه و وضعیت |
| POST | `/api/attendance` | ثبت دستی |
| PUT/DELETE | `/api/attendance/{id}` | ویرایش / حذف نرم |
| POST | `/api/attendance/{id}/restore` · `/revert` | بازگردانی / برگشت به مقدار دستگاه |
| GET | `/api/reports/daily` · `/summary` (+ `.csv`) | گزارش‌ها |
| GET | `/api/sync-runs` | سابقه هر بار تخلیه |
| GET | `/api/changes?after_rev=N` | خوراک تغییرات برای سامانه اصلی (درج/ویرایش/حذف با شماره rev) |

همه درخواست‌ها باید هدر `X-API-Key` داشته باشند.
