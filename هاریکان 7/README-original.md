# آرومین — سامانه حضور و غیاب

سامانه کامل حضور و غیاب با سه بخش:

| بخش | آدرس | کاربر |
|---|---|---|
| **پنل مدیریت** (React) | `/` | مدیر |
| **اپلیکیشن پرسنل** (PWA، روی اندروید و آیفون نصب می‌شود) | `/app` | پرسنل |
| **API و وب سرویس** | `/api` | پنل، اپلیکیشن، نرم‌افزارهای دیگر |

## ساختار پروژه
```
aromin-hozour/
├─ shared/core.js         ← «موتور»: محاسبه کارکرد، غیبت، اضافه‌کاری، تأخیر، مرخصی،
│                            بررسی سقف مرخصی و سیاست کاری، فاصله GPS — مشترک بین سرور و پنل
├─ server/                ← سرور (Node.js + Express + SQLite)
│  ├─ src/index.js        راه‌اندازی سرور، امنیت، مسیرها
│  ├─ src/db.js           دیتابیس (یک فایل SQLite) و جدول‌ها
│  ├─ src/auth.js         ورود، رمزنگاری رمز عبور (bcrypt)، توکن JWT، توکن وب سرویس
│  ├─ src/engine/
│  │  ├─ attendance.js    ثبت ورود/خروج: بررسی موقعیت، WiFi، قفل گوشی، زمان سرور
│  │  ├─ rules.js         اعتبارسنجی هر فرم، یکتا بودن کد/نام کاربری، جلوگیری از حذف وابسته
│  │  └─ sms.js           پیامک (کاوه‌نگار / ملی پیامک) طبق قوانین پنل پیامک
│  ├─ src/routes/
│  │  ├─ admin.js         API پنل مدیریت  (/api/admin/...)
│  │  ├─ app.js           API اپلیکیشن پرسنل (/api/app/...)
│  │  └─ v1.js            وب سرویس عمومی  (/api/v1/...)
│  ├─ src/zk/             پل دستگاه حضور و غیاب: client.js (اتصال به zk-sync) و bridge.js (تبدیل به کارکرد)
│  ├─ src/routes/zk.js    API دستگاه‌ها و ترددهای تخلیه‌شده (/api/admin/zk/...)
│  ├─ public/app/         اپلیکیشن پرسنل (PWA)
│  └─ test/api.test.js    ۹ تست خودکار کل سیستم
├─ zk-sync/               ← سرویس تخلیه دستگاه ZKTeco (پایتون، TCP 4370، فقط‌خواندنی)
├─ src/                   ← پنل مدیریت (۳۳ صفحه)
│  ├─ pages/Devices.jsx        تنظیمات کسب و کار ← دستگاه ها
│  ├─ pages/DeviceRecords.jsx  منوی «ترددهای تخلیه‌شده»
│  ├─ zk.js / zkMock.js        ارتباط با سرور / دستگاه شبیه‌سازی‌شده در نسخه نمایشی
└─ deploy/                ← فایل‌های نصب روی سرور (PM2، Nginx، پشتیبان)
```

## موتور چه کارهایی انجام می‌دهد
- **ثبت تردد امن:** ساعت از سرور گرفته می‌شود (گوشی قابل دستکاری نیست). ورود فقط داخل شعاع محل کار (با در نظر گرفتن خطای GPS تا ۵۰ متر) یا با اتصال به WiFi ثبت‌شده‌ی محل کار. قفل «یک دستگاه ثابت»، «فقط اندروید» و «فقط iOS». جلوگیری از ثبت تکراری.
- **محاسبه کارکرد:** حضور در شیفت، کسری، اضافه‌کاری، تأخیر، روز کارکرد، تردد ناقص. شیفت ساده (هفتگی) و سفارشی (ماهانه)، شیفت شب، تعطیلات رسمی، مرخصی ساعتی و روزانه.
- **سیاست کاری:** سقف مرخصی سالانه/ماهانه، سقف مرخصی ساعتی، حداکثر طول مرخصی، مهلت ثبت درخواست، فعال/غیرفعال بودن هر نوع درخواست، جلوگیری از درخواست‌های هم‌پوشان.
- **امنیت:** رمزها با bcrypt، ورود با JWT، محدودیت تلاش ورود، جدا بودن دسترسی مدیر و پرسنل، ثبت تاریخچه تغییرات (audit log)، رمز عبور هیچ‌وقت به پنل برگردانده نمی‌شود.
- **پیامک:** تایید/رد درخواست، درخواست جدید به مدیر، پیام جدید از پنل.
- **وب سرویس:** خروجی پرسنل، ترددها و کارکرد برای حسابداری و حقوق؛ دریافت تردد از دستگاه.

## دستگاه حضور و غیاب (ZKTeco، TCP 4370)
```
دستگاه ZK ──TCP 4370──► zk-sync (پایتون، 127.0.0.1:8470) ──► سرور اصلی (Node) ──► پنل
                         تخلیه خودکار / دستی              پل: هر ۳۰ ثانیه تغییرات
                         ذخیره بدون تکرار                  ← ورود/خروج در «کارکرد»
```
- **تنظیمات کسب و کار ← دستگاه ها:** افزودن و ویرایش دستگاه (نام، محل کار، IP، پورت 4370، رمز ارتباطی Comm Key)،
  **تست اتصال** (مدل، سریال، تعداد رکورد و کاربر)، **تخلیه خودکار** با بازه دلخواه ۱ تا ۱۴۴۰ دقیقه (مثلاً ۵ یا ۱۰۹)،
  دکمه **تخلیه الان**، وضعیت آخرین تخلیه و **سابقه تخلیه**.
- **منوی ترددهای تخلیه‌شده:** فیلتر (تاریخ شمسی، پرسنل، دستگاه، منبع، وضعیت)، **ویرایش**، **حذف نرم و بازگردانی**،
  **برگشت به مقدار اصلی دستگاه**، **ثبت دستی**، **تاریخچه تغییرات**، گزارش روزانه، خلاصه دوره و **خروجی اکسل**.
- **پرسنل دستگاه:** کدهای روی دستگاه که در سامانه تعریف نشده‌اند نشان داده می‌شوند (با دکمه «تعریف پرسنل با این کد»).
- **کارکرد خودکار:** «کد کاربر روی دستگاه» = «کد پرسنلی». ثبت‌های هر نفر در هر روز به ترتیب زمان به جفت ورود/خروج تبدیل
  می‌شوند (انگشت دوباره در کمتر از ۱ دقیقه یکی حساب می‌شود) و همه گزارش‌ها (کارکرد، تأخیر، اضافه‌کاری، تردد ناقص) از آن‌ها
  حساب می‌شوند. ویرایش یا حذف یک رکورد همان روز را دوباره محاسبه می‌کند. ثبت‌های اپلیکیشن و دستی پنل دست نمی‌خورند.
- **ایمنی:** هیچ رکوردی از دستگاه پاک نمی‌شود (دستورهای پاک‌کردن در سرویس مسدودند)؛ هر رکورد با کلید یکتای
  «دستگاه + کد + زمان + نوع» ذخیره می‌شود، پس تخلیه دوباره هیچ تکراری نمی‌سازد و رکورد ویرایش/حذف‌شده برنمی‌گردد.

### نصب سرویس دستگاه (روی همان سرور)
```bash
cd /opt/aromin-hozour/zk-sync
sudo bash deploy/install.sh          # پایتون، pyzk، سرویس systemd «aromin-zk» — در پایان کلید API را نشان می‌دهد
nano /opt/aromin-hozour/server/.env  # این سه خط را اضافه/تنظیم کنید:
#   ZK_SERVICE_URL=http://127.0.0.1:8470/api
#   ZK_SERVICE_KEY=<همان کلیدی که نصب نشان داد  (یا AZK_API_KEY در /etc/aromin-zk/aromin-zk.env)>
#   ZK_BRIDGE_SEC=30
pm2 restart aromin-hozour
```
بعد در پنل: تنظیمات کسب و کار ← دستگاه ها ← افزودن دستگاه ← تست اتصال ← ثبت ← تخلیه الان.
لاگ سرویس: `journalctl -u aromin-zk -f` · وضعیت: `systemctl status aromin-zk`

**شبکه:** دستگاه باید از سرور در دسترس باشد. اگر سرور در آروان است و دستگاه در دفتر: یا پورت 4370 مودم دفتر را فقط برای
IP سرور به IP دستگاه فوروارد کنید (و روی دستگاه Comm Key بگذارید)، یا دفتر و سرور را با WireGuard وصل کنید.
روش جایگزین: کل سامانه یا فقط zk-sync را روی یک مینی‌پی‌سی داخل دفتر نصب کنید و `ZK_SERVICE_URL` را به آن بدهید.

## اجرا روی کامپیوتر خودتان (برای تست)
نیازمند Node.js نسخه ۱۸ یا بالاتر.
```bash
npm install                 # وابستگی‌های پنل و موتور
npm --prefix server install # وابستگی‌های سرور
npm run build               # ساخت پنل
cp server/.env.example server/.env    # و مقادیر را ویرایش کنید
npm run server              # http://localhost:3000  و  http://localhost:3000/app
npm --prefix server test    # اجرای تست‌ها (۱۰ تست؛ تست دستگاه به python3 + fastapi نیاز دارد)
```
در زمان توسعه: `npm run server` در یک ترمینال و `npm run dev` در ترمینال دیگر.
نسخه نمایشی بدون سرور: `npm run dev:demo`.

## نصب روی سرور آروان (Ubuntu)
۱. **دامنه:** در پنل آروان‌کلاد یک رکورد A برای `hozour.arominco.com` به IP سرور بسازید.

۲. **نصب Node.js و ابزارها** (در کنسول WinSCP یا SSH):
```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs nginx certbot python3-certbot-nginx sqlite3
npm install -g pm2
```
۳. **آپلود پروژه** با WinSCP در پوشه `/opt/aromin-hozour` (بدون پوشه‌های `node_modules`).

۴. **نصب و ساخت:**
```bash
cd /opt/aromin-hozour
npm install && npm --prefix server install && npm run build
cp server/.env.example server/.env
nano server/.env     # JWT_SECRET، ADMIN_USER، ADMIN_PASS را عوض کنید
```
برای JWT_SECRET خروجی این دستور را بگذارید: `openssl rand -hex 32`

۵. **اجرای دائمی:**
```bash
pm2 start deploy/ecosystem.config.cjs && pm2 save && pm2 startup
```
۶. **Nginx و HTTPS** (برای موقعیت‌یابی گوشی، HTTPS **الزامی** است):
```bash
cp deploy/nginx.conf /etc/nginx/sites-available/hozour.arominco.com
ln -s /etc/nginx/sites-available/hozour.arominco.com /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d hozour.arominco.com
```
۷. **پشتیبان‌گیری روزانه:** `crontab -e` و افزودن خط  `0 3 * * * /opt/aromin-hozour/deploy/backup.sh`

۸. **بروزرسانی بعدی:** فایل‌های جدید را آپلود کنید، سپس
`npm install && npm --prefix server install && npm run build && pm2 restart aromin-hozour`

## مدیریت
- ساخت یا تغییر رمز مدیر: `npm --prefix server run create-admin -- admin رمز-جدید "نام مدیر"`
- نام کاربری و رمز پرسنل در «افزودن پرسنل» تعیین می‌شود؛ پرسنل با همان در `/app` وارد می‌شوند.
- آیفون: Safari ← آدرس `/app` ← Add to Home Screen. اندروید: Chrome ← «نصب برنامه».

## API — خلاصه
| مسیر | توضیح |
|---|---|
| `POST /api/auth/login` | ورود (مدیر یا پرسنل) |
| `GET /api/admin/bootstrap` | همه داده‌ها برای پنل |
| `GET/POST/PUT/DELETE /api/admin/c/:مجموعه[/:id]` | workplaces, shifts, personnel, requests, … |
| `GET /api/admin/reports/performance?from=&to=` | گزارش کارکرد |
| `GET /api/admin/reports/vacation?year=&month=` | گزارش مرخصی |
| `POST /api/app/clock` | ثبت ورود/خروج پرسنل `{lat,lng,accuracy,bssid,deviceId}` |
| `GET /api/app/me` | وضعیت امروز و ماه پرسنل |
| `POST /api/app/requests` | ثبت درخواست مرخصی/ماموریت/… |
| `GET /api/v1/attendance` · `/performance` · `/personnel` | وب سرویس (با توکن) |
| `POST /api/v1/punch` | ثبت تردد از دستگاه `{code,time,date?}` |
| `GET/POST/PUT/DELETE /api/admin/zk/devices[/:id]` | دستگاه‌ها · `POST …/devices/test` · `POST …/devices/:id/sync` · `POST …/sync-all` |
| `GET/POST/PUT/DELETE /api/admin/zk/attendance[/:id]` | ترددهای تخلیه‌شده · `…/:id/restore` · `…/:id/revert` · `…/:id/history` |
| `GET /api/admin/zk/reports/daily` · `/summary` · `/sync-runs` · `/people` · `/status` | گزارش‌ها، سابقه، وضعیت |

## محدودیت‌های فعلی
- دستگاه‌های ZKTeco با سرویس zk-sync پشتیبانی می‌شوند؛ برندهای دیگر (Virdi، Suprema، …) هنوز اتصال مستقیم ندارند و می‌توانند از `/api/v1/punch` استفاده کنند.
- ترددهایی که از نیمه‌شب رد می‌شوند (شیفت شب) در پل دستگاه هر روز جدا جفت می‌شوند؛ برای شیفت شب ورود/خروج را در «ترددهای تخلیه‌شده» بررسی کنید.
- اپلیکیشن پرسنل وب‌اپلیکیشن (PWA) است؛ نسخه APK/استور جداگانه ساخته نشده است.
- رهگیری موقعیت فقط وقتی اپلیکیشن باز است ارسال می‌شود (محدودیت مرورگرها).
- درگاه پرداخت «خرید پکیج» متصل نیست.
