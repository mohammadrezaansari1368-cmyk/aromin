# تب عملکرد: پیاده‌سازی، قرارداد داده و محدودیت‌ها

مبنای بررسی: `origin/main` در `0046a99`، نسخهٔ 3.9.52. گزارش مستقل «ممیزی-UX-تب-عملکرد-آرومین.md» در ورودی موجود نبود؛ یافته‌های نقل‌شده در مأموریت با کد فعلی تطبیق داده شدند. این تغییر ادغام یا نصب نشده است؛ دادهٔ اصلی، قواعد هفت مرحله، پورسانت، C4 و بودجه تغییر نکرده‌اند.

## مسیر نهایی

`PerformancePage` → `PerformanceWorkspace`: نمای مدیریتی با چهار کارت برای هر واحد، صفحهٔ فرد و سالانه، بررسی/تطبیق با موتور قبلی، تنظیمات مجزای مدیر و دسترسی صریح مدیر به ابزار legacy. افراد از فهرست اصلی می‌آیند، نه فقط فایل حضور. افراد غیرفعال مشخص‌اند؛ فرد بدون داده با «بدون داده» باقی می‌ماند. شناسه/نام ناقص یا شناسه تکراری مانع دریافت است تا نگاشت اصلاح شود.

فیلتر ماه/فصل/سال/بازه سفارشی، واحد و شخص مشترک است؛ سال تقویم سالانه کنترل جدا دارد. تغییر دامنه پاسخ قبلی را پنهان و درخواست را لغو می‌کند. خروجی Excel همهٔ صفحات همان دامنه را از API مجاز می‌خواند؛ چاپ/PDF تنها صفحهٔ فعلی جزئیات است. URL فیلترها در این نسخه ذخیره نمی‌شود؛ مسیر اصلی برنامه نیز مدیریت URL مشترکی برای این تب ندارد.

شاخص‌های کمکی: وظایف از `people.perf.dailyTasks`، حضور از موتور موجود فایل محلی. وظایف روزانه رکورد تجمیعی‌اند و ادعای ریز تک‌وظیفه ندارند. تقویم قرارداد **تعداد** را نشان می‌دهد؛ جزئیات هر قرارداد **مبلغ تومان** و شناسه همان اسناد را دارد. نقش‌های خارج از سه واحد کارت تخصصی جعلی ندارند. هدف معتبر، مقایسه دوره مشابه، امتیاز عمومی و رتبه‌بندی سیاستی تولید نشده است.

قرارداد: مقدار nullable، واحد، تعریف، صورت/مخرج، دوره، زمان منبع، پوشش رکورد/مسئله، وضعیت و منبع. نبود داده `null` است؛ صفرِ صریح وظیفه صفر می‌ماند. جمع سازمان از صورت/مخرج رکوردهاست، نه میانگین میانگین افراد. رکوردهای قرارداد با `(سال مالی، شناسه سند)` رفع تکرار می‌شوند؛ تعارض محتوا/مالک حذف و گزارش می‌شود. کلیدهای متفاوت یک روز وظیفه نیز بدون جمع حدسی کنار گذاشته می‌شوند.

تاریخ قرارداد از `saleDate` معتبر یا `stageChangedAt` با پارسر موجود؛ تاریخ وظیفه از کلید همان روز؛ زمان مالی از audit و تبدیل `Asia/Tehran`. سال مالی از فیلد/باکت اصلی حفظ می‌شود و از تاریخ تقویمی ساخته نمی‌شود. مقدار/تاریخ نامعتبر حذف و دلیل گزارش می‌شود. هیچ بازپردازش یا نوشتن روی داده رخ نمی‌دهد.

## API و مجوز

`GET /api/performance/{directory|source|summary|daily|details}` با `tenant` و هدرهای احراز هویت موجود `kb_identity`:

- manager: سازمان؛ salesmgr: فروش/آنلاین؛ accmgr: مالی؛ سایر حساب‌ها: شخص دارای نگاشت یکتا و فعال.
- نگاشت ترجیحاً `personId`؛ در دادهٔ فعلی نام دقیق و یکتای `user.person` به شناسه اصلی resolve می‌شود. نام مبهم یا حساب بی‌نگاشت 403.
- `person`, `unit`, `start`, `end` در هر درخواست کنترل می‌شوند؛ روزانه فقط برای یک شخص؛ جزئیات `offset/limit` حداکثر 200.
- directory فهرست مجاز؛ source فقط شناسه/نام/نقش/غیرفعال و `dailyTasks/dayStatus/dayType`؛ سالانه فقط خلاصه روزانه؛ جزئیات فاقد مشتری، رمز و کل سند است.
- source موتور حضور را تغذیه می‌کند؛ نگاشت ضعیف محلی وارد پردازش نمی‌شود. فایل خام/آمار همهٔ کارکنان به خروجی کاربران غیرمدیر سازمان اضافه نمی‌شود.
- تجمیع روی همان blob فعلی انجام می‌شود؛ schema، index، cache و سرویس موازی ایجاد نشده‌اند. هزینه با اندازه blob رشد می‌کند؛ سنجش بار تولید انجام نشده است.

**محدودیت امنیتی مهم:** API قدیمی `GET /api/state` در معماری فعلی عمومی است و مصرف‌کنندگان دیگر، از جمله مسیر قدیمی ورود/legacy، به آن وابسته‌اند. مسیرهای جدید عملکرد از آن استفاده نمی‌کنند و جداسازی آن‌ها تست شده؛ اما این PR به معنی جداسازی سراسری اطلاعات برنامه نیست. همچنین فایل‌های واردشده قبلی در IndexedDB یک مرورگر مشترک، ذخیره امن چندکاربره نیستند. بستن این دو مسیر نیازمند مهاجرت احراز هویت مصرف‌کنندگان و ذخیره‌سازی حضور به منبع دارای مجوز است؛ در این تغییر برای حفظ سازگاری پنهانی بازنویسی نشده‌اند. قبل از ادعای امنیت کامل و انتشار برای کاربران نامطمئن باید رفع شوند.

## حضور، تطبیق و اختلاف ۸۶۳/۱۰۲۴

حضور، فایل خام وظایف، نگاشت و تنظیمات هنوز در ذخیره‌ساز موجود مرورگر هستند. خلاصه جدید وظایف، تمام روزهای معتبر منبع سرور را مستقل از حضور می‌شمارد؛ تطبیق قبلی بر **شخص‌ـ‌روز دارای حضور** محاسبه می‌شود. بنابراین جمع وظایف و شمار شخص‌ـ‌روز یک واحد/دامنه نیستند. زمان حضور دقیقه است؛ قرارداد تومان؛ فعالیت مالی سند.

ارقام واقعی ۸۶۳ و ۱۰۲۴ با فایل اصلی و پایگاه تولید در این محیط قابل بازتولید نبودند؛ منشأ عددی اختلاف مشخص نشده و ادعای رفع آن نمی‌شود. مسیر تفکیک دامنه و جزئیات اکنون قابل مشاهده است. fixture مصنوعی ثابت می‌کند جمع روزانه ۰+۳ = ۳ با جزئیات یکسان است و میانگین قراردادهای ۱۰۰،۳۰۰،۵۰۰ برابر ۳۰۰، نه میانگین میانگین افراد است. برای تطبیق قطعی دو عدد، فایل حضور/وظایف، زمان snapshot، فیلتر و نگاشت همان گزارش لازم است.

## سالانه و Skyline

کامپوننت `contribution-skyline.tsx` از قبل در main بود؛ نصب مجدد انجام نشد. API واقعی آن `{date,count}` با تاریخ میلادی و بازه چرخان ۳۶۵ روز، شروع هفته ۰/۱ و تبدیل نبود روز به صفر است. مجوز مستقل قابل اتکا در فایل‌های موجود پیدا نشد. استفادهٔ قبلی بدون داده واقعی حذف شد؛ فایل اصلی و وابستگی‌های آن تغییر نکردند. 3D با قرارداد موردنیاز سازگار نیست و در این نسخه فعال نشده است.

جایگزین مجاز: دوازده ماه شمسی واقعی با شنبه اول هفته، کبیسه، انتخاب شاخص واحد، tooltip/نام قابل خواندن، کلیک و صفحه‌کلید. در موبایل ماه‌ها زیر هم و اندازه روزها ثابت‌اند، کل سال فشرده نمی‌شود. صفر، نبود داده، آینده و مرخصی/تعطیل ثبت‌شده حضور با علامت جدا هستند. تعطیلی برای شاخص‌های فاقد آن داده حدس زده نمی‌شود. رنگ نسبت به بیشینه همان سال است؛ متن مقدار نیز وجود دارد. انیمیشن اضافه نشده و reduced motion مانعی ندارد. تاریخ همکاری تاریخی موجود نیست؛ روزهای خارج از همکاری حدس زده نمی‌شوند.

اجرای مجدد از ریشه مخزن، با Python دارای FastAPI و uvicorn و محیط دارای Playwright/Chromium:

```bash
python -m unittest discover -s deployment/tests -v
cd frontend
npx vitest run
npm run lint
npm run build
```

در ترمینال‌های جدا از ریشه:

```bash
python -m uvicorn performance_fixture_api:app --app-dir deployment/tests --host 127.0.0.1 --port 5192
npm --prefix frontend run dev -- --host 127.0.0.1 --port 5191
node frontend/tests/browser/performance-workspace.cjs
```

fixture تنها برای localhost و داده مصنوعی است؛ در production mount نشود. ماژول تازه در install/rollback/package_requirements ثبت شد تا انتشار آینده server با import مفقود مواجه نشود؛ بسته یا نصب در این مأموریت انجام نشده است.
